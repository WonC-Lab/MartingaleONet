## Data preparation and immutable split mechanics

Price rows count individual parameter/state queries. Initial training plan:256 unique parameter blocks,192 broad-support blocks and64 near-Feller blocks, with the latter sampled by recorded rejection from the same broad support. State queries per block use50% broad,25% ATM-short and25% low-v mixtures. Sobol scrambling and mixture-choice RNG streams are separate and saved. Growing training size adds query rows and, when needed, independently seeded train-only parameter blocks; zero parameter-block overlap with dev/final sets. All scaling prefixes are nested; mixture counts and block counts are logged rather than claimed exactly proportional after rounding.

Interpolation tests use broad parameter support with IID state draws and equal block weighting. Boundary tests tag exact/near terminal,v0,x guard boundaries and near-Feller conditions. Exact tau0 payoff is scored for values only; Greeks at the ATM kink are excluded with counts. OOD tests have predeclared axis tags, including weak/positive rho and sigma>support. Every test reference must satisfy E01 tolerances or appear as uncertified coverage; no favorable filtering after model evaluation. Standard metrics average per block then over blocks to prevent a densely sampled easy surface dominating. Plot-slice arrays are descriptive and not extra IID statistical replications.

## E08/E09 hedging ledger and simulation certification

Primary contract grid: regimesR0/R1/R4 from E01, moneynessS0/K={.9,1.1},tau={.25,1};S0=100,v0=.04,K=100/moneyness,r as in regime. R4 is explicitly OOD, not pooled unnoticed with interpolation. ATM contracts can be added as a separately tagged development/follow-up population before final freeze; no choosing favorable strikes after PnL results. Primary interpolation hypothesis is evaluated on R0/R1; R4 is stress/OOD secondary. Rates/variance/model inputs are identical across strategies at each date.

Use a separately validated Heston QE-M/appropriate martingale-preserving time-discretization simulator, based on [Andersen's simulation study](https://www.maths.univ-evry.fr/pages_perso/crepey/Finance/andersen%20vol%20sto.pdf), not the legacy clipped Euler paths. Pin algorithm,parameters,random variates and implementation. Numerical scheme correction is not a claimed P-to-Q transformation and is unrelated to the discarded temporal normalization. Check E[S_T]=S0exp(rT) within MC confidence bands, exact CIR variance moments,negativity/NaN counts,option payoff MC confidence agreement with E01 and h/h2/h4 refinement on common drivers where legitimate coupling is implemented. Severe regimes may need a finer grid or exact/independently validated subset; label unresolved paths, do not clip variance just to pass checks. Grid resolution/error should be smaller than the hedge-strategy gap or conclusions are inconclusive.

Base planned simulation252steps/year; hedge-grid dates daily/weekly, and2/day sensitivity requires refining simulation to504steps/year, not interpolating daily paths and claiming finer rebalancing. A prospective252/504/1008 refinement study on at least2000 shared-path contracts checks numerical bias. Final number/date grid must be frozen before comparative hedging. All paths are stored once and referenced by hash. No separate random simulation per strategy.

Strategies: unhedged; analytic referenceDelta_A; independent numerical/COSDelta_B (mustagree within Greek tolerance); B02Delta;B03Delta;B08Delta;B06/B05Delta when available; secondary reference local variance-minimizing stock hedge V_S+(rho*sigma/S)V_v. No learned policy optimization. Observedv is a controlled-simulation assumption, not a market deployability claim. Use referenceinitialcallprice for every primary strategy; own-surrogatepremium is a separate accounting sensitivity.

At t0 cash B0=P_ref-h0*S0-alpha*S0|h0|. For each rebalancej>=1,

`B_j=B_(j-1)*exp(r*dt_j)-S_j*(h_j-h_(j-1))-alpha*S_j*abs(h_j-h_(j-1))`.

Accrue final interval interest at T; primary convention liquidates stock atT, payingalpha*S_T*|h_last|, settles European payoff, and calculates `Pi=B_last*exp(r*dt_final)+h_last*S_T-alpha*S_T*abs(h_last)-payoff`. No closing hedge rebalance in addition to liquidation. Record every cash/trade/interest/TC component; unhedgedcash accrues identical total time. Primary transaction costs apply opening,rebalances,andliquidation; a no-liquidation convention, if shown, is separate. Never mix them in figure labels.

Use positive-loss VaR/ES definitions in HYPOTHESES. PnL dispersion includes incompleteness; improvement in reference-Delta gain deviation need not improve total PnL. Secondary locally minimizing reference shows the volatility-risk floor without promising perfect replication. Costs from variance-instrument hedging are outside scope.

## E10 matched performance protocol

Freeze certified reference tolerances to meet the relevant error budget. Reference production implementation must be vectorized over contracts, reuse CF/coefficients across genuinely shared inputs in the surface workload, and handle large heterogeneous batches by chunking with logged memory/cost. Heterogeneousquery andsame-parameter surface cases are separately reported. Never disable reference convergence in one method only to gain speed. Learned andreference predictions are evaluated on identicalquery rows andprecision requirements.

CPU benchmarks use the same machine and process policy, documented core affinity where available, and fixed thread counts. Report a single-thread result and a separate declared multi-thread setting. Use float64 for the reference; compare float64 neural inference as the primary same-precision result, with a separately labelled float32 variant only after accuracy checks. Record any dtype difference.

GPU benchmarks compare methods on the same physical GPU only if a validated production GPU reference exists. Otherwise report standalone GPU model throughput without a CPU-reference/GPU-model speedup ratio. Do not manufacture a slow GPU reference just to create a comparison.

Separate price-only from price-plus-Delta/Gamma/nu workloads. Document AD graph allocation, reference preparation and caching, tensor conversions and memory. Use 20 warm-up batches, 200 timed repetitions per batch and three sessions with randomized method order. CPU uses a high-resolution clock; GPU uses events and synchronized wall timing before/after the measured region. Measure both device-resident computation and host-to-output end-to-end latency including transfers under the same allocation policy. Model loading, compilation and first-call startup are separately reported.

Persist every repetition, including tagged scheduler outliers. Summarize median, IQR, p95, batch milliseconds, microseconds per contract and contracts per second. Compare identical input arrays and verified accuracy configurations.

Total amortization cost includes price labels, Greek labels, training and model selection. If the workload-specific per-contract cost saving d is positive, approximate break-even contracts as total cost/d, with consistent wall-time or monetary units. If d<=0 there is no crossover. Do not mix CPU and GPU costs without explicit accounting. This is a workload-specific calculation, not a universal real-time claim.

## Failure handling and dependencies

Required shared artifacts include certified reference version, split/label manifests, reference uncertainty, checkpoint/config hashes, optimizer/RNG states, raw predictions and derivatives, constraint grids, common-path hashes and ledgers, timing repetitions and failure masks. A failed run is never replaced by a zero placeholder. Metric provenance follows CLAIM_EVIDENCE_MATRIX.

Dependencies will be pinned in Phase 1B, not installed now: Python, NumPy, SciPy, mpmath and optional QuantLib. Future training uses Torch; typed records may use pandas/pyarrow and future figures matplotlib. The large framework, training, real-market data, multi-asset expansion and deployment are NOT-NEEDED-YET in Phase 1A.
